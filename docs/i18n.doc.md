# Internationalization (EN / FR / ES / AR)

This document is the source of truth for languages, localized URLs, copy
ownership and right-to-left layout. Read it before adding copy, links or
direction-dependent CSS.

## Goals

- The first byte of HTML is already in the visitor's language and direction.
  Nothing is translated, measured or swapped in the browser.
- Pages stay statically generated and CDN cached. One URL serves exactly one
  language, so the cache never varies on headers.
- Translation strings never enter the client bundle unless a client control
  genuinely needs them, and then only that control's own strings.
- Every language must look as finished as English: copy fits the same space,
  headings break where the English breaks, Arabic is a real right-to-left
  layout.

## URLs and detection

`src/i18n/routing.ts` is the single table. English keeps bare URLs; other
languages are prefixed and use translated route segments:

| Folder | EN | FR | ES | AR |
| --- | --- | --- | --- | --- |
| services | `/services` | `/fr/services` | `/es/servicios` | `/ar/خدمات` |
| projects | `/projects` | `/fr/projets` | `/es/proyectos` | `/ar/مشاريع` |
| about | `/about` | `/fr/a-propos` | `/es/sobre-nosotros` | `/ar/من-نحن` |
| contact | `/contact` | `/fr/contact` | `/es/contacto` | `/ar/تواصل-معنا` |
| faq | `/faq` | `/fr/faq` | `/es/preguntas-frecuentes` | `/ar/الأسئلة-الشائعة` |
| privacyandpolicy | `/privacyandpolicy` | `/fr/confidentialite` | `/es/privacidad` | `/ar/سياسة-الخصوصية` |

Project slugs (`pr15-1`) are language-neutral and never translated.

`next.config.ts` turns the table into static rewrites (public URL to the
`src/app/[locale]/<folder>` route) and redirects:

1. `/en/...` permanently redirects to the bare URL.
2. An English segment under another language (`/fr/projects`) permanently
   redirects to its translation (`/fr/projets`).
3. Bare English URLs only: a `locale` cookie redirects to that language; with
   no cookie, the primary `Accept-Language` tag decides. Prefixed URLs are
   never redirected, so a shared link opens in the language it was sent in.

The cookie is written only by an explicit choice in the header switcher.
There is no middleware: the rules run in the router before the cache.

## Rendering

- `src/app/[locale]/layout.tsx` is the root layout. It prerenders every
  language and renders `<html lang dir>` on the server.
- Every page awaits `resolveLocale(params)` from `@/i18n/server` and passes
  the `Locale` down as a prop. Server components receive `locale`; there is
  no locale context and no `useTranslation`.
- Page metadata uses `pageMetadata({ locale, path, title, description })`
  from `@/i18n/metadata`, which adds canonical and hreflang alternates.
- Not-found boundaries receive no params: they render each language and CSS
  keeps the one matching `html[lang]`.

## Copy ownership

Copy lives in server-only modules next to the server component that renders
it. Two shapes are allowed:

```ts
// <name>.copy.ts — small component copy
import type { Locale } from "@/i18n/routing";

const en = {
  title: "Who we are",
  cta: "Learn more",
};

export const heroCopy: Record<Locale, typeof en> = {
  en,
  fr: { title: "Qui sommes-nous", cta: "En savoir plus" },
  es: { title: "Quiénes somos", cta: "Saber más" },
  ar: { title: "من نحن", cta: "اعرف المزيد" },
};
```

`Record<Locale, typeof en>` makes a missing or extra key a type error, so a
language can never silently fall back to English.

For collections (`_data/*.ts`) keep the structure once (ids, slugs, images,
dimensions, hrefs) and put only the text per language, keyed by a stable id,
then expose a `get<Collection>(locale)` function that returns the merged
records. Long-form content may use one file per language in a folder
(`_data/privacy/en.ts`, `fr.ts`, ...), each typed against the English shape.

Rules:

- Never import a `.copy.ts` or `_data` module from a `"use client"` file or
  anything a client file imports. `npm run test:ssr` enforces this.
- Client components receive their strings as props from their server parent.
  Client hooks receive labels as arguments; a dynamically imported motion
  module receives them through its loader's props.
- Strings rendered by the DOM for cursor labels or status messages may be
  passed through `data-*` attributes on server markup.
- Brand and proper names stay in Latin script: Artefact Studio, Vawzen,
  Behance, Upwork, WhatsApp, Telegram, Instagram, project names.

## Links

Every internal `href` goes through `localizePath(englishPath, locale)`:

```ts
localizePath("/projects/pr15-1", "fr"); // "/fr/projets/pr15-1"
localizePath("/contact?mode=contact", "es"); // "/es/contacto?mode=contact"
```

Write English paths in data and convert at render time. Never hardcode a
`/fr` prefix or a translated segment.

## Writing the translations

- French: formal "vous", correct accents and typography (`é`, `à`, `ç`,
  `œ`), a narrow no-break space (` `) before `? ! : ;` and inside
  `« »`.
- Spanish: friendly "tú", opening `¿` and `¡`, neutral international
  vocabulary.
- Arabic: Modern Standard Arabic, conventional UI imperatives, Western digits
  (0-9), Arabic punctuation (`،` `؟` `؛`). Keep acronyms such as CGI or 3D
  in Latin where that is how the industry writes them.
- Keep the English meaning and tone; do not add or drop claims.
- Length budget: navigation, buttons, chips, labels, headings and any text in
  a fixed-width or single-line slot must fit the English footprint (aim for
  no more than ~10% more characters, and prefer a shorter synonym over a
  literal translation). Body paragraphs may run up to ~20% longer. If English
  uses a deliberate line break (`<br />`, separate spans), give each language
  its own break at a natural point. Never shrink type to make copy fit.
- Numbers and dates: format with `Intl` and `intlLocale(locale)` from
  `@/i18n/format`.

## Right-to-left

`dir="rtl"` is set on `<html>` for Arabic. In CSS modules:

- Use logical properties where placement should follow reading direction:
  `margin-inline-start`, `padding-inline-end`, `inset-inline-start`,
  `border-inline-start`, `text-align: start`.
- Mirror direction-dependent transforms and keyframes under
  `:global([dir="rtl"]) .selector { ... }`.
- Flip directional icons (arrows, chevrons) with `scale: -1 1` under RTL.
- Do not mirror 3D canvases, videos, photographs, logos, the cursor, or
  numbers.
- Arabic must not be letter-spaced or case-transformed; `globals.css` resets
  `letter-spacing` for Arabic globally.
- Keep each CSS module's existing formatting (many are one line per selector
  with the formatter disabled in `biome.json`).

## Language switcher

While the full-screen menu is open, the header shows every language as a
code (`EN FR ES AR`) beside the close button; the current one is underlined.
It fades in after the menu's reveal has covered the page and fades out first
when it closes, using only opacity and transform, and is `inert` while the
menu is closed, so the closed header looks exactly as it did before languages
existed. Choosing one writes the `locale` cookie and then performs a full
document navigation to the same page in that language, so the introduction
replays and every scene boots in the new language, exactly as a reload would.
Its links carry `data-locale-switch`, which the page transition ignores.

## Fonts

- Latin text, digits and brand names use Poppins through next/font, exactly as
  before.
- Arabic uses Readex Pro, chosen after comparing Readex Pro, Alexandria and IBM
  Plex Sans Arabic on the live Arabic pages: it matches Poppins' geometric
  construction and colour and keeps Arabic copy compact. It is one 23 KB
  variable woff2 (`public/assets/fonts/readex-pro-arabic-v27.woff2`) declared
  in `globals.css` for the Arabic Unicode range only.
- It is self-hosted instead of using next/font so the root layout can preload
  it on Arabic pages only (`ARABIC_FONT_URL` in `src/config/fonts.ts`); next/font
  would preload it on every page that shares the layout.
- Under `html[lang="ar"]`, body puts "Readex Pro" first in
  `--font-family-base`. Because of the unicode-range, Latin characters fall
  through to Poppins. The variable is declared on `body`, where next/font
  defines `--font-poppins`; on `html` the reference would be unresolved.
- `font-display: block` keeps Arabic invisible for the instant the preloaded
  file needs, under the introduction, instead of swapping a fallback.

## 3D scenes

Only the how-it-works scene contains text: one Spline `TextGeometry`, laid out
at runtime from a TTF. The VR mark is vector geometry and stays "VR" in every
language; the process scenes have no text.

`node scripts/localize-spline-scenes.mjs` writes
`public/assets/landing-page/how-it-works/am-arc-how-it-works.scene[.<locale>].splinecode`
from the English scene. A `.splinecode` file is msgpack (msgpackr records)
with five Spline extension types and round-trips byte for byte, so each
language differs only in the title text, its font, its size and its text box.
Titles were chosen to cover the English footprint ("Le processus", "Así
funciona", "طريقة العمل"); the script only ever shrinks a title that would
outgrow it. Each scene points at a self-hosted TTF subset of its own title's
glyphs (`fonts/how-it-works-<locale>.ttf`, 1.7 to 6.8 KB) instead of the
155 KB font the editor exported from fonts.gstatic.com. The regenerated
English scene renders within the scene's own frame-to-frame noise of the
original.

### Stills

`how-it-works-mobile[.<locale>].jpg` is both the mobile fallback and the
desktop placeholder under the canvas. Each still is a tight crop of the title,
800 px wide, rendered from the localized scene with the title tilted by
`rotation.x - 0.055` (the pose that reproduces the original English still,
correlation 0.98). To regenerate one: load the scene with the Spline runtime
in a page the size of the desktop viewport, apply that tilt, screenshot,
crop to the bright pixels and downscale to 800 px.

The desktop placeholder box was fitted to the English still.
`PLACEHOLDER_FIT` in `src/lib/howItWorks3d/howItWorks.shared.ts` offsets and
scales that box per language (fractions measured from the renders), so each
still lands over its own live title; English stays exactly as before.

## Verification

- `npx tsc --noEmit`, `npx biome check`, `npm run test:ssr`,
  `npm run test:i18n`.
- `npx next build`: every `[locale]` route must stay `●` (prerendered).
- Visual review of every section in every language at 390, 768, 1440 and
  1920 px wide, comparing each against English for overflow, wrapping,
  clipping and RTL placement. The review compares, per element, the number of
  lines each language wraps to against English and flags text outside its box
  or the viewport; shorter copy is the fix, never a smaller font.
- Initial payload versus the single-language build: about +2 KB gzipped
  JavaScript per route (the switcher and the route table), +1.5 to 2.3 KB HTML
  (hreflang links and switcher markup), and the Arabic font preload on Arabic
  pages only.
